SEMANA 10

Programación orientada a objetos y APIs REST

Aplicación de principios de POO en una herramienta CLI de gestión de productos y construcción y prueba de un backend REST con Express y MySQL.

01

APRENDIZAJE

Temas aprendidos

Tema 01

POO y herencia en Python

La programación orientada a objetos organiza datos y comportamiento en clases. La herencia permite especializar productos por categoría y el polimorfismo ofrece una interfaz común para trabajar con distintos tipos. Un mixin permite reutilizar capacidades mediante herencia múltiple.

Tema 02

Encapsulamiento y validación

El encapsulamiento protege el estado del producto y centraliza las reglas de validación. Las excepciones personalizadas comunican errores del dominio, como una categoría inválida, y permiten que la aplicación responda sin perder el control del flujo.

Tema 03

Backend REST con Express y MySQL

Una API REST expone recursos mediante rutas HTTP. Express procesa las solicitudes y un pool de conexiones MySQL facilita el acceso a la base de datos. Las respuestas JSON y sus códigos de estado permiten que el cliente conozca el resultado de cada operación.

ACTIVIDADES

Gestión de productos y desarrollo backend

Semana 10 · Actividad 01

Sistema de Gestión de Productos (CLI)

Descripción

Se implementó una aplicación de consola en Python 3.12 o superior para administrar productos. El menú permite agregar productos, listar el inventario y calcular el precio final. El modelo aplica herencia, herencia múltiple con mixin, encapsulamiento, polimorfismo y excepciones personalizadas.

Los productos incluyen categoría, nombre, precio base y stock; los productos electrónicos también registran meses de garantía.

Procedimiento

  1. Presentar un menú interactivo para agregar y listar productos o calcular su precio final.
  2. Solicitar categoría, nombre, precio y stock, además de los datos específicos requeridos por el tipo de producto.
  3. Validar la categoría y los valores ingresados; comunicar los datos incorrectos con una excepción personalizada.
  4. Crear productos mediante clases y especializaciones que reutilizan y sobrescriben comportamientos.
  5. Comprobar el alta correcta, el listado y el manejo de una categoría no válida desde la consola.

Resultados

Las capturas muestran el menú CLI, el registro de un producto electrónico, el listado del inventario y la validación que rechaza una categoría no admitida.

Semana 10 · Actividad 02

API REST de productos con Express y MySQL

Descripción

Se implementó un backend con Node.js y Express para exponer operaciones REST sobre productos y conectarse a una base de datos relacional MySQL mediante un pool de conexiones. Las solicitudes y respuestas se verifican con una colección de pruebas HTTP en Postman.

Las evidencias documentan la consulta de la colección, la obtención de un producto por identificador, la respuesta cuando no existe, la creación de un producto y su eliminación.

Procedimiento

  1. Configurar la conexión a MySQL con un pool y definir el recurso de productos en el servidor Express.
  2. Implementar rutas para listar, consultar, crear, actualizar y eliminar productos.
  3. Validar los datos del cuerpo de la solicitud y ejecutar las consultas parametrizadas correspondientes.
  4. Responder con JSON y códigos HTTP apropiados, incluidos 201 para una creación y 404 cuando el producto no existe.
  5. Probar las solicitudes desde Postman y verificar los cuerpos y códigos de respuesta.

Resultados

La colección de Postman muestra productos obtenidos desde la API, la consulta por ID, la respuesta 404 para un producto inexistente, la creación con respuesta 201 y la eliminación correcta de un producto.

03

REFLEXIÓN

Reflexión personal

¿Qué aprendí?

Aprendí a estructurar una solución orientada a objetos para representar productos y sus variantes, validar sus datos y manejar errores de dominio. También reforcé el diseño de rutas REST y el uso de códigos HTTP para comunicar el resultado de operaciones sobre una base de datos.

¿Cómo aprendí?

Practiqué primero las operaciones del inventario desde una interfaz CLI y después observé las solicitudes y respuestas de una API mediante Postman. Las pruebas de casos exitosos y de recursos inexistentes ayudaron a relacionar la lógica del servidor con la experiencia del cliente.
